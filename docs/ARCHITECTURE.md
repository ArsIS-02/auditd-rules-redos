# aarch64 и x86_64: чем отличаются правила

## Системные вызовы

aarch64 использует общую («generic») таблицу системных вызовов Linux, в которой
нет устаревших вызовов, работающих с путём от текущего каталога. Их заменяют
варианты `*at`, принимающие дескриптор каталога. glibc вызывает именно их,
поэтому правило на `chmod` на aarch64 не только не загрузится
(`Syscall name unknown`), но и не нужно.

Номера ниже сверены с таблицами `audit-userspace` (`lib/aarch64_table.h`,
`lib/x86_64_table.h`, `lib/i386_table.h`).

| Операция | x86_64 (номер) | aarch64 (номер) |
|---|---|---|
| сменить права | `chmod` 90, `fchmod` 91, `fchmodat` 268 | `fchmodat` 53 |
| сменить владельца | `chown` 92, `fchown` 93, `lchown` 94, `fchownat` 260 | `fchownat` 54 |
| открыть файл | `open` 2, `openat` 257 | `openat` 56 |
| удалить | `unlink` 87, `rmdir` 84, `unlinkat` 263 | `unlinkat` 35 |
| переименовать | `rename` 82, `renameat` 264, `renameat2` 316 | `renameat` 38, `renameat2` 276 |
| создать каталог | `mkdir` 83, `mkdirat` 258 | `mkdirat` 34 |
| жёсткая ссылка | `link` 86, `linkat` 265 | `linkat` 37 |
| символическая ссылка | `symlink` 88, `symlinkat` 266 | `symlinkat` 36 |
| сокет | `socket` 41 | `socket` 198 |
| модули ядра | `init_module` 175, `finit_module` 313, `delete_module` 176 | 105, 273, 106 |

Проверить на хосте:

```bash
ausyscall aarch64 fchmodat     # 53
ausyscall x86_64 chmod         # 90
ausyscall --dump | less        # вся таблица текущей архитектуры
```

В журнале архитектура видна в поле `arch`: `c00000b7` — aarch64,
`c000003e` — x86_64, `40000003` — i386 (32-битный процесс на x86_64).

## 32-битные приложения (`arch=b32`)

**x86_64.** 32-битные программы делают системные вызовы по таблице i386, где
номера другие. Правило `arch=b64` их не видит, поэтому для сокетов и модулей
ядра в наборе есть пары правил `b64` + `b32`. Ограничение: старые 32-битные
программы создают сокеты через мультиплексор `socketcall(2)` (102), а не через
`socket` (359), — правило с `-S socket` их не поймает.

**aarch64.** 32-битные ARM-процессы возможны только при включённой в ядре
поддержке compat. На хостах этого набора 32-битного пользовательского
окружения нет, поэтому правил `arch=b32` нет — `deploy.sh` откажется ставить
на aarch64 файл, в котором они есть.

## SELinux

Правила с `-F subj_type=...` сравнивают SELinux-тип процесса. При
`SELinux Disabled` у процессов нет типа, такое правило не загружается и
обрывает загрузку остального файла.

| | aarch64 | x86_64 |
|---|---|---|
| SELinux на хостах | Disabled | Enforcing |
| Правила `subj_type` | нет | исключения для `crond_t` |
| Если SELinux выключен | — | `deploy.sh` вырезает строки `subj_type` при установке |

Исключение по `crond_t` убирает события самого демона cron. Задания cron
работают в другом домене (`system_cronjob_t`, `unconfined_cronjob_t`) и
продолжают аудироваться.

## Пути к программам

В РЕД ОС `/bin` и `/sbin` — символические ссылки на `/usr/bin` и `/usr/sbin`.
Правила `-w /sbin/auditctl -p x` работают: ядро разрешает каталог-родитель по
ссылке. В журнале путь исполняемого файла будет каноническим
(`exe="/usr/sbin/auditctl"`), учитывайте это в фильтрах SIEM.

## Число правил

| | aarch64 | x86_64 |
|---|---|---|
| `-w` | 45 | 45 |
| `-a` | 10 | 15 (13 без SELinux) |
| Итого в `auditctl -l` | **55** | **60** (58) |

Служебные строки `-D`, `-b`, `-f` в `auditctl -l` не попадают.
